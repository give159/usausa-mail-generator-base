# 特典2：第三者向け手順書 時短・穴埋めテンプレート

うさうさ研修工房「複利エンジニアリング入門」受講生特典（2026年11月版）

「自分は分かっているが、他の人に渡すと伝わらない」を防ぐための、穴埋め式の手順書テンプレートです。Claudeに下書きを任せて、短時間で形にします。

## この特典について

- 手順の中に出てくる**事実（コマンド、設定、画面の説明）は、公式資料に書かれているものだけ**にしています。記入例は、VS Code公式のWindowsセットアップ資料の記載に合わせました。
- 穴埋めの欄の型と、Claudeへの依頼文は、この特典のために作ったひな形です。公式資料の記載ではありません。自分の現場に合わせて直してください。

## 使い方（3ステップ）

1. **穴埋めシート**（下の「A」）に、分かる範囲で答えを書く。箇条書きで構いません。
2. **依頼文**（下の「B」）に穴埋めシートを貼って、Claudeに渡す。
3. 出てきた手順書を、**チェックリスト**（下の「E」）で確認し、**第三者に1回やってもらう**（下の「F」）。

## A. 穴埋めシート（ここだけ自分で書く）

```
手順書のタイトル：【　　　　　　　　　】
読み手：【だれが読むか。例：新入社員、他部署の担当者】
読み手の前提：【OS、できること、できないこと】
ゴール（完了の状態）：【この手順が終わったとき、何ができていればOKか】
所要時間の目安：【　　分】
事前に用意するもの：【アカウント、ファイル、権限など】
手順の大枠（3〜7個）：
  1.【　　　　　】
  2.【　　　　　】
  3.【　　　　　】
自分が確認済みの環境：【OS・ソフトのバージョン・確認した日】
よくあるつまずき：【分かっている範囲で】
参照する公式ページ：【URL】
困ったときの連絡先：【人・部署・URL】
```

- 分からない項目は、空欄のままで構いません。Claudeが `[要確認]` と書いて残します。

## B. Claudeへの依頼文（コピペ用）

````
次の穴埋めシートをもとに、第三者向けの手順書を作ってください。

【守ってほしいルール】
- シートに書いていない事実は、書かない。必要な場合は [要確認] と書く。
- コマンドや設定の説明は、シートに書かれた公式ページの内容だけを根拠にする。
- 1つの手順では、1つの動作だけを書く。
- コマンドや入力する文字は、コードブロックにする。
- 各手順に「期待される結果」を書く。
- 読み手が迷いそうな言葉は、初出のときに短く説明する。
- 最後に「困ったときの確認表」と「完了チェック」を付ける。

【型】
下の「C. 手順書の型」に沿って書く。

【穴埋めシート】
（ここに A を貼る）
````

## D. 記入例：Windowsに VS Code を入れる手順（抜粋）

VS Code公式（https://code.visualstudio.com/docs/setup/windows）の記載に合わせた例です。

| 項目 | 内容 |
|---|---|
| 対象の読み手 | Windows を使う新入社員 |
| 確認した環境 | 【作成者が確認したWindowsのバージョンと日付を書く】 |
| 参照した公式ページ | https://code.visualstudio.com/docs/setup/windows |

**STEP 1　インストーラーを入手する**
- やること：VS Code公式サイトから、Windows用の User setup をダウンロードする
- 期待される結果：`VSCodeUserSetup-{バージョン}.exe` というファイルが保存される
- 補足：User setup は管理者権限が不要で、更新もスムーズなため、公式が推奨しています

**STEP 2　インストーラーを実行する**
- やること：ダウンロードしたファイルを実行し、画面の案内に従って進める
- 期待される結果：インストールが完了する
- 補足：セットアップは、VS Codeを PATH に追加します

**STEP 3　PowerShellで起動を確かめる**
- やること：コンソールを**開き直して**、次を入力する

```powershell
mkdir fukuri-lab
cd fukuri-lab
code .
```

- 期待される結果：VS Code が起動し、`fukuri-lab` フォルダが開く
- うまくいかないとき：`code` が認識されない場合は、コンソールを閉じて開き直す（PATHの反映に再起動が必要）

**完了チェック**
- [ ] VS Code が起動した
- [ ] `code .` でフォルダを開けた

## E. 品質チェックリスト（出力を受け取ったら必ず人が確認する事項）

- [ ] 読み手が、自分以外の人でも一人で最後までできる内容になっている
- [ ] 1つの手順に、動作が1つだけ書かれている
- [ ] すべての手順に「期待される結果」がある
- [ ] コマンドや入力文字が、コードブロックになっている
- [ ] 専門用語が、初出のときに説明されている
- [ ] `[要確認]` が残っていないか、残っているものは自分で確かめた
- [ ] 手順に書かれた事実が、参照した公式ページの記載と合っている
- [ ] 書かれたコマンドを、自分の環境で実際に実行して確かめた
- [ ] 確認した環境（OS・バージョン・日付）が書かれている
- [ ] 困ったときの確認表と連絡先がある

---

## F. 第三者テスト

1. 手順書を知らない人に渡し、**口を出さずに**やってもらう。
2. つまずいた箇所に、印をつける。
3. 印をつけた箇所を手順書に反映する（説明を足す、手順を分ける、確認表に追加する）。

---

## G. 時短のコツ

- 穴埋めシートは、完璧に書かなくて大丈夫です。分かる所だけで書いてください。
- Claudeの出力は、そのままお客様に第三者向け手順書 時短・穴埋めテンプレート渡さないでください。必ず最後に責任者ががEを確認してください。
- 公式ページは更新されます。手順書の「最終更新」と「参照した公式ページ」を、必ず書いておきましょうね！
